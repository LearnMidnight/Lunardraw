# Lunardraw

A self-running lottery for AI agents on the Midnight network. Weekly Starfall draws with verifiable randomness from [Nightcast](https://github.com/LearnMidnight/Nightcast), private entries and on-chain claims. A stalled round is cancelled and refunded, never redrawn. Testnet only.

**Status:** **Starfall runs on Preprod** since 27 Oct 2026: contract `46fb810f8c36140f8d0b2119d0b554504310f8002ef5667b278c5fd6789326bf`, hourly test draws (record in [deployments/starfall-preprod.json](deployments/starfall-preprod.json), check it with `./lunardraw starfall verify --network preprod`). Its first draw sold 76 games, settled them privately in 4 batches and paid 3 winners automatically, 14 minutes after sales closed. CI runs a full Starfall draw with real proofs on a local Midnight network. The v0 soak (#5, 24-27 Oct, contract `5bb124ee…6ec5`, [deployments/preprod.json](deployments/preprod.json)) has ended. Test tokens only.

## Starfall

Pick 7 numbers from 1–35 and a Moonball from 1–20. Tickets cost a fixed price per line in tNIGHT (1 to 5 lines a ticket). The prize pool is the draw's ticket sales plus any rollover, split across nine divisions, from 7 + Moonball (30%) down to 2 + Moonball; a division nobody wins rolls over to the next draw.

## How a draw stays honest

- **Secret tickets.** Only a commitment to your numbers goes on chain. You reveal one winning line (its division, not its numbers) when you claim it.
- **Nobody knows the numbers during sales.** The keeper bot seals a random seed before sales open and reveals it after they close; the Nightcast oracle then answers with a VRF output that anyone can check, and the numbers follow from both with a fixed public rule. The keeper can't compute the oracle's answer, and the oracle can't change the seed.
- **Nothing gets stuck.** Every stage has a deadline. If the keeper or the oracle stops, anyone can void the draw and every ticket is refunded in full.
- **No quiet key swaps.** A draw is bound to the oracle key that is active when it opens, so you can see which key will answer before you buy. A new key has to wait longer than any draw sells for (unless the current oracle agrees), and the wait is public.
- **Rolling draws.** Revealing one draw's seed opens the next, so the draws run week after week. Draws settle in order, and the rollover always goes to the next draw in line.

The full design, including the trust that remains, is in [docs/DESIGN.md](docs/DESIGN.md).

## Next: private, automatic settlement

Where Starfall is heading: no claim button, and no ticket's numbers ever made public. `contract/src/settlement.compact` is a second contract built on the same draw, in which:

- the game is Australian Powerball's: 7 from 35 plus a Moonball from 20, nine divisions, Powerball's prize-pool allocation, jackpot rollover and no-winner rules, a game costs 1.2 tNIGHT, of which 1 tNIGHT goes to the prize pool and 0.2 tNIGHT to the operator, per line;
- every ticket is published as a commitment plus the ticket encrypted to a settlement key; up to 18 tickets per transaction (a System, Pick or Moonball Sweep entry is one ticket), with QuickPick packages from Single (1) to Maxi (50);
- a settler works through every ticket in order, 25 per proof, and the contract checks that each one matches its commitment, so no ticket can be left out, counted twice or altered;
- prizes are then paid automatically by anyone;
- if settlement misses its deadline, every ticket is refunded.

It has 12 circuits, the most that fit in a deploy transaction, and v0's oracle-key and organiser fixes. It's tested in the simulator with 100 private tickets and every failure case; not deployed yet. Syndicates are designed and tested on branch `starfall-syndicates` and wait for a later contract. Design, guarantees and the privacy that remains: [docs/SETTLEMENT.md](docs/SETTLEMENT.md).

## Building and testing

You need Node 22 and the Compact toolchain 0.31.1 (`compact update 0.31.1`).

```sh
git clone --recurse-submodules https://github.com/LearnMidnight/Lunardraw
cd Lunardraw
npm install
npm run compact   # compile Nightcast's and Lunardraw's contracts (no proving keys)
npm run build
npm test
```

`npm run compact:keys` also builds the proving keys (about 10 minutes; the `computeNumbers` key is about 145 MB).

To move to a newer Nightcast: `git -C nightcast fetch && git -C nightcast checkout <commit>`, run the tests, then commit the new `nightcast` pointer.

## Running it

Step by step for Preview, with a draw every 30 minutes: [docs/preview-guide.md](docs/preview-guide.md).

Wallets, the oracle key and the Blockfrost project id are Nightcast's files (see Nightcast's [Preprod guide](https://github.com/LearnMidnight/Nightcast/blob/main/docs/preprod-guide.md)); run its tools with `nightcast/nightcast`.

```sh
npm install && npm run compact:keys && npm run build
./lunardraw keygen organiser --out ~/lunardraw-secrets/organiser.secret
./lunardraw keygen organiser --out ~/lunardraw-secrets/backup.secret     # keep this one offline
./lunardraw deploy --network preview --organiser ~/lunardraw-secrets/organiser.secret \
  --backup ~/lunardraw-secrets/backup.secret --oracle oracle.secret --wallet wallet.secret --accept
./lunardraw keeper --network preview --organiser ~/lunardraw-secrets/organiser.secret --wallet wallet.secret
./lunardraw oracle --network preview --oracle oracle.secret --wallet oracle-wallet.secret   # on another machine
./lunardraw status --network preview
./lunardraw verify --network preview
```

**Run your own proof server.** The organiser secret (keeper) and the oracle key (oracle) are sent to the proof server to build each proof, so each must use a proof server on its own machine; the tools start one in Docker that only that machine can reach. Never point them at a hosted or shared proof server.

`./lunardraw keeper ... --feed <file>` also writes the website's feed (`lunardraw-feed/1` JSON, marked `"contract": "lunardraw-v0"`) after every pass; serve that file from a public URL for the site to read, or load it by hand with `wp lunardraw sync --file=<file>`.

The defaults are the weekly Starfall: Thursdays 20:00 Brisbane, 1 tNIGHT a line. For a test network, deploy with shorter windows, for example `--min-sales 600 --reveal 600 --draw 900 --claim 3600`, and run the keeper with `--every 1800` for a draw every 30 minutes. The keeper keeps its sealed seeds in `~/lunardraw-secrets/seeds-<network>.json`: back it up and keep it private.
